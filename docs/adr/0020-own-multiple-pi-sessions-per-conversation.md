# Own multiple Pi sessions per ClawChat conversation

A ClawChat conversation owns a Conversation Session Set rather than one immutable Pi session: authoritative discovery creates an empty Active Chat Session, `/new` preserves non-empty history while selecting a fresh session, and `/resume` may select only history owned by the same `chat_id`. This preserves cross-chat isolation while bringing Pi's session lifecycle into ClawChat; global Workspace resume was rejected because it would expose another conversation's context, and replacing history was rejected because it would make Pi-style resume impossible.

Conversation work is durably serialized as one FIFO containing both Chat Turns and Session Commands, so a Session Transition deterministically separates work targeting the former and replacement Active Chat Sessions across restarts. `/stop` deliberately sits outside that FIFO to mirror Pi Escape: it aborts the active Turn and cancels earlier queued work, while completed tool effects remain irreversible. Session lifecycle commands require the Agent owner even though ordinary admitted participants retain Pi execution authority, because switching or stopping changes shared conversation state.

This supersedes the one-session-per-`chat_id` and per-session-queue portions of ADR-0003 and ADR-0007 without changing their cross-chat isolation or deterministic-ordering goals. Output Mode remains scoped to the ClawChat conversation, and a confirmed Agent group leave deletes the group's complete Conversation Session Set while reliable-delivery deduplication state remains intact.
